# Control loop and authority

V3 has two planes. The control plane owns scientific meaning and state; the
execution plane performs bounded work. An execution result is only a candidate
artifact until the control plane records provenance, uncertainty, scope, and a
decision about its inferential role.

## Control-plane loop

1. Diagnose the request and load only the needed domain/study references.
2. Read existing project state and native registries before creating duplicates.
3. State a beginner brief, argument skeleton, risks, budget, and permissions.
4. Select the next graph node from unmet inputs and decision relevance.
5. Staff capabilities and qualify external employees before formal evidence.
6. Execute the node with a producer and, when load-bearing, an independent checker.
7. Register artifacts and anchors; update claims only from verified evidence.
8. Decide `PASS`, `CONDITIONAL`, `FAIL`, reopen, amend, narrow, or stop.
9. Report completed/current/next/largest risk and any author checkpoint.

## Authority boundaries

The agent may autonomously perform low-risk, reversible, locally verifiable work.
The author must decide scope changes, competing scientific interpretations,
ethics, resource commitments beyond the declared budget, disclosure choices,
and any upload, release, submission, or account action. The agent may recommend
but may not silently make those choices.

## Status vocabulary

Use `PLANNED`, `READY`, `RUNNING`, `BLOCKED`, `PASS`, `CONDITIONAL`, `FAIL`,
`REOPENED`, `SUPERSEDED`, and `WITHDRAWN`. A status change must include a UTC
timestamp, actor/employee, reason, evidence or command anchor, and next owner.
