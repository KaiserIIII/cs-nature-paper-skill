# Research Autopilot

Autopilot is a bounded discovery and execution mode, not autonomous science.
It starts from a direction, question, codebase, dataset, draft, or rejection.

## Start sequence

1. Extract the stakeholder problem and what the author hopes to know or enable.
2. Create a beginner research brief with knowns, unknowns, constraints, and
   vocabulary; mark assumptions instead of asking a long questionnaire.
3. Classify domain and study type, then load exactly one profile of each.
4. Run a small orientation search for a survey, seminal work, recent strong
   work, closest work, and known negative or contradictory evidence.
5. Explain the minimum concepts needed for the next choice.
6. Build a field map and unresolved-question list with source identities.
7. Generate candidate RQs and mechanisms; generators are hypotheses, not proof.
8. Run the closest-work and prior-art adversaries.
9. Run a feasibility screen over hardware, data, access, complexity, cost,
   license, ethics, expertise, and timeline.
10. Score options by evidence fit, decision value, risk, cost, and reversibility;
    recommend one bounded default.
11. Checkpoint the author only if the choice changes the question, scope,
    resources, ethics, or public state.
12. Activate the graph and stop when a gate, budget, or missing critical input
    requires the author.

## Budget and stop rules

The budget records token/tool calls, wall time, network, compute, money, private
paths, and allowed external writes. Autopilot stops on exhaustion, unsupported
claims, contradictory sources, missing provenance, unqualified employees,
protocol amendments, ethical uncertainty, or external release. It never invents
results/citations, promotes pilot outcomes, changes an RQ silently, or submits.
