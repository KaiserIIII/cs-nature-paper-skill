# V3.1 synthetic end-to-end example

This is a public-safe workflow example, not a publication claim. The student
says:

> “I want to study LLM-based Python code repair. I have little research
> training. Please stay within a personal-computer budget and explain the
> decisions that require my approval.”

The V3.1 control loop records the following bounded path:

1. `orientation` and `brief` translate the request into a small vocabulary,
   scope, candidate outcome, and a beginner-readable question.
2. `literature` records discovery queries separately from identity and
   full-text claim-support checks. Snippets and abstracts cannot become
   load-bearing support.
3. `innovation` and `prior_art_red_team` write a contribution contract with
   closest work, mechanism, alternative explanation, falsifier, and the result
   that would remain if the idea fails.
4. `feasibility` compares compute, data, API cost, licenses, timeline, and
   reproducibility. A high-cost plan is narrowed to a representative fixture
   or an open model before any formal run.
5. `pilot` runs a tiny deterministic fixture. Only after pilot failure modes
   are recorded can the author freeze a formal protocol.
6. `implementation`, `formal_experiment`, `analysis`, and `evidence_update`
   retain failed runs, estimands, uncertainty, hashes, and checker identity.
7. `figures` and `writing` consume the evidence ledger; they cannot add a
   stronger claim than its relationship (`SUPPORTS`, `QUALIFIES`,
   `CONTRADICTS`, or `MISSING`).
8. `validation`, threat-selected `review`, and targeted `revision` reopen an
   evidence investigation when a claim is unsupported.
9. `venue_preflight` checks current primary rules. `artifact_package` and
   `author_handoff` stop at an explicit author decision before upload or
   submission.

The included `scripts/smoke_run.py` executes this shape with a synthetic
project, a local artifact, a deep evidence anchor, a claim-linked pilot plan,
the native/external capability resolver, a method route, a literature query,
and an answer-hidden routing case. It reports `NOT_RUN` for model comparison
because no second model is available; that state is not converted to a score.
