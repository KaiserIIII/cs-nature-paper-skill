# V3.1 Baseline Audit

Audit date: 2026-08-27  
Audited repository: `KaiserIIII/cs-nature-paper-skill`  
V3 release commit: `f9db7dcece402167f36784f7336bc04405c4a6fc`  
Baseline: remote `v3`, compared with `v2` (`e42e9d6f0a515a72f6bdb639516c492b73d8f68c`) and preserved historical `v1`/`main`.

This audit is based on the checked-in files and executable entry points, not on
the V3 release narrative alone. The local V3 worktree also contains the same
uncommitted implementation that was published as the V3 release candidate;
the V3.1 changes must be based on the published V3 content.

## Inventory

- `SKILL.md` is a compact V3 control-plane prompt with Guided/Copilot/Autopilot routing.
- `scripts/research_state.py` initializes, audits, and migrates private state.
- `scripts/research_graph.py` validates a graph, reports status, and appends simple transitions.
- `scripts/evidence_anchor.py` validates the anchor shape and a ledger collection.
- `scripts/employee_registry.py` audits the seven-department registry and supports registry operations.
- `assets/evals/behavior_cases.json` defines V3 cases; tests validate the case structure.
- `assets/schemas/` contains only `evidence_anchor.schema.json`.
- `assets/templates/` contains V2 and V3 templates in one directory; initialization strips `_v3` from output names.
- `references/domains/` and `references/study-types/` are routing cards; method depth and runtime routing are not executable.
- No `skill_router.py`, experiment planner, graph executor, behavior runner, release manifest builder, or GitHub Actions CI exists.
- Historical `v1`, `v2`, and `main` remain separate remote refs. V3 is one commit ahead of V2 and does not modify those refs.

| D1 | V3 names capability coverage, qualified employees, and least privilege. | Marketplace guidance is policy text; no machine-readable capability resolver or delegation plan execution. | MAJOR | A task can be assigned to an unqualified or mismatched provider. | Students still need to know which skill/agent to invoke. | No `inventory`, `resolve`, `team`, or plan validation command. | Add capability taxonomy, skill catalog, resolver, delegation-plan schema, and normalized handoff. | Router unit/integration tests and pressure cases for missing capability, quarantine, permissions, and cost. |
| D2 | Graph validates dependencies and records transition events. | It is not an executor: no conditional planning, readiness, advance, reopen, rollback, supersession, or rebuild. | MAJOR | A graph status can imply progress without executing or checking the required artifact. | Autopilot cannot reliably explain or continue the next step. | Only `validate`, `status`, and `transition` are implemented. | Add immutable event log plus materialized projection and executor commands. | Conditional graph fixtures, rebuild hash checks, and end-to-end smoke run. |
| D3 | Domain and study-type files expose useful routing hints. | Profiles are thin cards and do not resolve method decisions or escalation triggers. | MAJOR | Wrong estimand, baseline, or inference method can pass through routing. | Beginner receives labels without a concrete recommendation. | No method expert router or deep method modules. | Add machine-readable method router and bounded method modules; route high-risk decisions to qualified specialists. | Method routing fixtures and forbidden-claim tests. |
| D4 | Behavior cases enumerate important V3 safety behaviors. | Cases are definitions only; expected behavior is visible in the same fixture and no runner stores environment or compares versions. | MAJOR | Safety and integrity regressions can go undetected. | No trustworthy indication that the assistant actually followed cases. | No `prepare`, `run-record`, `score`, `compare`, or `report`. | Add answer-hidden runner, environment manifest, deterministic scoring, and V2/V3/V3.1 comparison format. | Runner tests with a local deterministic adapter; unavailable model runs remain `NOT_RUN`. |
| D5 | Existing tests cover state, graph, anchors, registry shape, and case schema. | Most assertions are structural; no workflow, behavior, or end-to-end research benchmark exists. | MAJOR | Structural validity is not evidence of scientific behavior. | Regressions in student-first recommendations are invisible. | No Level 2-4 test separation or smoke fixture. | Add integration tests, security pressure tests, benchmark cases, and one public-safe smoke run. | Pytest/unittest layers and benchmark report with case-level verdicts. |
| D6 | V3 documents validation and release intent. | CI, manifest generation, schema registry validation, and release automation are absent. | MAJOR | A broken release can be published without reproducible checks. | Users cannot see what was actually verified. | No `.github/workflows/ci.yml` or deterministic manifest builder. | Add dependency-light CI, optional model-eval workflow, release manifest, and generated SHA manifest. | Run CI-equivalent command locally and inspect workflow YAML. |
| D7 | V3 migration preserves V2 state in a separate directory. | V2/V3 templates and output names are ambiguous; there is no single canonical schema registry or explicit V3.1 versioning. | MAJOR | New state may be initialized from the wrong template or lose provenance. | Users cannot tell which state files are authoritative. | `init_state` strips `_v3`, and schema coverage is incomplete. | Separate `assets/templates/v3/` and `assets/legacy/v2/`, add all core schemas, explicit migration metadata, and safe unknown-version failures. | Migration byte-preservation tests and schema/template validation. |
| D8 | V3 has evidence-bound claim language and an anchor schema. | Anchor validation does not verify local artifacts, hashes, commits, commands, or checker requirements. | MAJOR | `PASS` can be asserted from non-empty strings rather than inspectable evidence. | Completion messages can overstate what was verified. | No `--deep` verification or evidence relationship semantics. | Add deep verification, relationship enum, artifact/hash checks, and conditional external-resource status. | Local fixture with matching/mismatching hashes, missing artifacts, and checker requirements. |
| D9 | V3 recognizes discovery, pilot, formal, replication, and reproduction stages. | No experiment planner, long-job manifest/checkpoint runtime, statistical producer/checker, or figure provenance runtime exists. | MAJOR | Experiments can be outcome-independent, untracked, or incorrectly promoted to formal evidence. | Student receives no cost/information-gain recommendation. | No executable planner or completion semantics. | Add experiment planner/registry validation, bounded job runtime records, and provenance-aware evidence updates. | Planner decisions, checkpoint/resume fixtures, and smoke experiment. |
| D10 | V3 contains authority, privacy, and no-fabrication principles. | Runtime enforcement and pressure tests are incomplete; public upload, credentials, prompt injection, and destructive actions are not exercised. | MAJOR | Unauthorized external action or private-data leakage remains a release risk. | Boundaries are documented but not demonstrated. | No security pressure harness or least-privilege plan validator. | Add authority matrix, security fixtures, catalog permission checks, and explicit `AUTHOR_ACTION`/`BLOCKED` statuses. | Security pressure suite and negative-action assertions. |

## Baseline release decision

V3 is a strong architecture baseline but is **not V3.1 release-candidate ready**:
the missing runtime components are goal-blocking MAJOR defects. V3.1 will only
claim readiness after deterministic tests, workflow integration, behavior
harness execution, an end-to-end smoke run, and the five required red-team
audits produce zero CRITICAL and zero goal-blocking MAJOR findings. Remaining
MINOR defects and unavailable external model runs must be reported explicitly.
