## Scope

V3.2 adds maximum-autonomy execution around the v3.1.1 research control and
execution planes. Ordinary reversible work is automatic; bounded higher-impact
work is audited; fundamental author-only and unsafe work remains blocked. The
candidate includes a complete isolated AUTO_HIRE lifecycle, evidence-bound node
executors, per-node self-healing budgets, project `READY_FOR_SUBMISSION`
completion semantics, and separate software release integrity. The CUMCM
runtime is integrated as a clock/risk/ETA overlay that reuses authorization,
execution, evidence, audit, recovery, and graph contracts.

The final CUMCM specialization adds a real Competition Director that reads and
decomposes every supplied problem, makes a qualitative automatic selection
when one option clearly dominates, routes mixed methods, executes a baseline
and formal solver, verifies feasibility/units/numbers, runs sensitivity,
generates traceable figures and a Chinese paper, performs judge-style review
and automatic repair, and stops at `COMPETITION_SUBMISSION_READY`. Temporary
clock and ETA restrictions remain policy projections rather than canonical
scientific graph transitions.

The provider-final hardening adds a host-neutral Provider Runtime without
replacing the control plane. Research and competition nodes resolve qualified
native, installed Skill, host/tool, or public-web providers; every result is a
typed artifact that must pass a deterministic checker before evidence or graph
state changes. Provider artifacts record input hashes, provider identity and
version, command/tool records, upstream IDs, and creation time. Upstream changes
mark dependent work stale.

The final host/generalization hardening makes host execution an explicit,
resumable lifecycle. A Python provider can only create a request and return
`HOST_EXECUTION_REQUIRED`; the current host must produce observed artifacts and
a typed handoff before an independent checker can accept it. The Director keeps
the node `RUNNING`, resumes the same node after acceptance, and reopens completed
formal-experiment, analysis, figure, writing, and review descendants when host
code changes.

The research constant/trend implementations and the bounded competition method
families are now identified as native baselines. Native-unsupported recorded
classification and graph-network cases request problem-specific host code (and,
for competition, a per-question host model plan), then execute that returned
code through the normal deterministic runtimes. These tests validate routing,
handoff, execution, and checking; they do not evaluate a live model.

Skill discovery no longer copies a search query into a candidate's capability
set. Formal AUTO_HIRE requires `CONFIRMED` semantic verification plus static
audit, behavior trial, output contract, and checker. Literature discovery now
distinguishes metadata, retrieved full text, and independently verified exact
regions; metadata-only load-bearing novelty or closest-work claims block the
completion contract.

AUTO_HIRE can now begin from a capability vacancy rather than a caller-supplied
source directory. The production path searches configured catalogs and public
GitHub backends, audits relevant metadata and source files, resolves an exact
40-character commit, materializes only low/medium-risk candidates in isolation,
qualifies, executes with a no-secrets environment, checks, and accepts. Public
network tests remain recorded/mocked in CI.

The legacy research example and logistics solver are explicit test providers.
Production research execution is project-aware and input-derived. Production
competition execution routes by question structure and handles mixed
forecasting/optimization, evaluation/clustering, and simulation/ODE problems.

## Scientific integrity

The v3.1.1 provenance, evidence, research graph, scientific gates, privacy and
security pressure behavior, and regression tests remain authoritative. Declared
or pilot artifacts cannot be upgraded to formal evidence. The full-paper run is
classified `HARNESS_SELF_TEST`; it is not a model behavior evaluation, venue
claim, publication result, or scientific generalization. No third-party
dependency or Skill was installed, and no external write, publication,
submission, tag rewrite, or main merge was performed.
