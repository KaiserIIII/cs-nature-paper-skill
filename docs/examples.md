# Safe usage examples

These examples show routing and expected artifacts. They intentionally avoid
fabricated results, venue rules, reviewer votes, and acceptance predictions.

## 1. Plan an empirical study

```text
Use $cs-nature-paper in plan mode. My data are repository snapshots and I want
to study dependency portability. Define the constructs, fixed-target scope,
mechanism, RQs, estimands, denominators, dependence structure, and falsifiers.
Do not authorize data collection until the argument gate passes.
```

Expected output: a research contract, construct table, claim/evidence skeleton,
protocol risks, and explicit decision gates. It should not invent hypotheses or
universal experiment counts.

## 2. Recover from rejection privately

```text
Use $cs-nature-paper in revision mode. Treat the attached editorial letter as
confidential. Freeze the rejected manuscript and analyses, classify each concern
as framing, construct, theory, design, interpretation, or venue fit, and draft a
dated analysis amendment before proposing new work.
```

Expected output: a concern-to-change matrix and a bounded revision program. The
letter stays local and is not quoted into a public repository.

## 3. Decide whether to add environments

```text
The editor questioned a single-target design. Build the expansion decision
table for two runtimes and two operating systems. For each addition, name the
threat tested, prediction, decision-changing outcome, and cost. Preserve the
original frozen campaign and label the new campaign separately.
```

Expected output: an inferential justification for each environment. “Shows
effort” or “proves commitment to the venue” is not a scientific reason.

## 4. Audit a prerequisite claim

```text
Audit every use of reproducibility in this manuscript. We measured package
resolution only. Scope unsupported claims and state the downstream boundary at
first use. Produce a claim-to-evidence matrix with file or table anchors.
```

Expected output: resolution may be described as a necessary workflow gate when
justified, but not as successful installation, execution, testing, numerical
reproduction, or repository reproducibility.

## 5. Run a preflight

```text
Use $cs-nature-paper in preflight mode for the current EMSE submission. Verify
template, article type, anonymity, page guidance, declarations, data policy,
AI policy, and submission fields from current publisher or journal sources.
Record the URLs and verification date. Do not upload or submit anything.
```

Expected output: a requirements card with primary-source links, an artifact
audit, and author-only actions. Static rules remembered from a previous year do
not pass the gate.

## 6. Review without acceptance theater

```text
Review this draft from editor, dependency-ecosystem, empirical-method, and
adversarial perspectives. Keep production and judgment roles separate where
the host supports it. Report CRITICAL, MAJOR, and MINOR findings with evidence
anchors; do not manufacture votes or predict acceptance.
```

Expected output: independent findings when independent agents were actually
used, otherwise explicitly labeled perspectives from one agent.

## 7. Staff a high-stakes full run

```text
Use $cs-nature-paper in full mode. Define the capability contract for all seven
departments, inventory the reviewed installed skills, and audit any missing
employee before suggesting installation. Separate producers from checkers for
literature, innovation, implementation, figures, and writing. Do not let an
unassessed or quarantined employee affect formal evidence.
```

Expected output: a bounded team manifest, employee registry, department
coverage report, handoff contracts, and explicit `PASS`, `CONDITIONAL`, or
`FAIL` results. Team size alone is not a quality measure.

## 8. Upgrade figures without inventing evidence

```text
Use the figure department to redesign the main figures. Start from frozen source
tables, make one figure contract per claim, choose truthful encodings, render
deterministically, and have a separate checker recompute values and inspect the
compiled manuscript at final size. Image generation must not create data marks.
```

Expected output: source tables, plotting code, vector/raster exports, manifest,
captions, alt text, and a source-to-mark audit rather than decorative mock data.

## 9. Promote exploratory code to formal evidence

```text
Use the implementation department. Preserve the exploratory notebook, define
the environment contract, move the selected analysis into a tested deterministic
entry point, retain failed cases, hash formal inputs and outputs, and verify the
documented reproduction command from a clean environment.
```

Expected output: a frozen protocol-to-code trace, tests selected by failure risk,
formal-output manifest, and explicit boundaries on what the checks establish.
