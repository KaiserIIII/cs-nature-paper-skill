# V3.1.1 Hardening Release Report

Date: 2026-08-27. Base: V3.1 commit `5a75f5021c47ebd4a57c001196ac3fd718ec389c`.
This report describes only the `v3.1.1-hardening` branch. `main`, `v1`, `v2`,
`v3`, and `v3.1` are preserved and are not rewritten or merged.

## What changed

- Manifest hashes are LF-normalized and include only release-controlled source;
  generated benchmark runs, temporary state, caches, and release metadata are
  excluded. `check_smoke.py` rejects a result whose `skill_commit` differs from
  the tested `git rev-parse HEAD`.
- The release manifest separates source version/commit, generation time,
  deterministic tests, hosted CI, model behavior, E2E status, and limitations.
  The source commit is publisher-injected because a file cannot hash itself.
- `smoke_run.py` executes a public local fixture, records a real execution
  record and hashes, performs literature identity and region support checks,
  plans an experiment, creates node-specific anchors, validates the graph event
  chain, rebuilds the projection, and runs a harness self-test. It does not
  force graph nodes to PASS or claim a scientific result.
- `privacy_lint.py` and `sanitize_artifact.py` prevent local paths, credentials,
  tokens, and private review markers from public artifacts.
- Capability resolution now accepts purpose, load-bearing status, and
  criticality. `PROVISIONAL` is advisory-only. A `SPECIALIST` needs an exact
  pin, a relevant passed behavior trial, permissions, and activation scope
  before formal evidence work. Resolution remains distinct from execution;
  `handoff_runtime.py` validates the host handoff and checker contract.
- Evidence has `DECLARED`, `OBSERVED`, and `VERIFIED` levels. Observed/formal
  anchors require an execution record; exit status and output hashes come from
  the runtime, not a user assertion. Git commits and content hashes are checked.
- Literature support records retrieval method, URI, retrieval time, source
  hash when available, inspected region, and inspection actor. Snippet or
  abstract-only support is conditional. Method routing returns `UNRESOLVED` on
  zero reliable matches and exposes ambiguity and specialist escalation.
- Experiment ranking is qualitative by default and retains why/claim/threat
  decision records; fake decimal precision is rejected.

## Verification

Local deterministic gates pass: unit and integration tests, full dependency-free
schema subset validation, registry consistency, manifest check, privacy lint,
security pressure harness, and the true local E2E fixture. The E2E result has
21 graph events and 19 node-specific evidence anchors; its class is
`HARNESS_SELF_TEST`, not `MODEL_BEHAVIOR`.

Hosted GitHub Actions status is recorded as `PENDING` until the pushed branch's
matrix is observed. No model behavior trial was available in this host, so it
is `NOT_RUN`; the deterministic harness is not presented as a model pass.

## Release gate

There are no known critical or goal-blocking major defects in the local
implementation. The strict disposition is **V3.1.1 NOT READY** until hosted
CI is observed green and the unavailable model evaluation is explicitly kept
as `NOT_RUN` or run through an authorized isolated model adapter. No merge to
`main` is recommended automatically.
