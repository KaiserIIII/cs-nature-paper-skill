# V3.1 five-perspective red-team audit

Audit date: 2026-08-27. Each pass used the implementation and its generated
fixtures. Findings were fixed in the working tree and the affected checks were
rerun. These are bounded engineering audits, not independent human review.

## A. Research Scientist

- Finding: a graph transition could be mistaken for a scientific result.
- Fix: `research_graph.advance` only materializes readiness and blocks; `PASS`
  requires an evidence anchor, while claims require an observed anchor and a
  final status.
- Recheck: graph integration tests and the 18-node smoke run pass.

## B. Methodologist

- Finding: a planner could spend resources on outcome-independent work and a
  methods choice could be inferred from a vague prompt.
- Fix: `experiment_planner` drops unlinked/outcome-independent options except
  named diagnostic, safety, venue, or reproducibility work; `method_router`
  returns estimands, assumptions, checks, escalation, and forbidden claims.
- Recheck: planner integration test and method route in smoke output pass.

## C. Research Software Engineer

- Finding: mutable graph state had no verifiable history and long jobs could
  appear complete without outputs.
- Fix: JSONL events carry predecessor/event hashes and `rebuild` replays them;
  `job_runtime.complete` requires real output files and records output hashes.
- Recheck: tamper-rebuild and checkpoint/resume/completion tests pass.

## D. Agent / Security Architect

- Finding: a broad skill collection, embedded prompt, credential request, or
  public action could cross the task boundary.
- Fix: capability-first least-privilege routing, quarantined catalog entries,
  answer-hidden evaluation, explicit author-action states, and fail-closed
  security pressure fixtures were added. The evaluator now matches complete
  behavior phrases, avoiding single-word false positives.
- Recheck: all 11 deterministic security pressure cases pass; full external
  model execution remains a separate host-owned trial.

## E. Undergraduate User

- Finding: the old first screen led with architecture vocabulary and required
  the student to name a skill or statistical test.
- Fix: README and `SKILL.md` now begin with a one-sentence student workflow;
  the CEO selects capabilities, offers lower-resource alternatives, and asks
  only for material scientific, ethics, resource, or publication decisions.
- Recheck: synthetic beginner routing case passes; representative student
  usability evidence is still an explicit residual risk.

## Disposition

No known critical or goal-blocking major defect remains in the deterministic
implementation. Remaining conditional items are external model/host trials,
live venue pages, and network-blocked rechecks of some third-party repos.
