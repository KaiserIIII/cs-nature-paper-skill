# V4.1 Provider and Review Contracts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the first executable V4.1 contracts for independently qualified providers, PUBLIC_CORE fallback, and reviewer synthesis/checker separation without changing the V4 control plane.

**Architecture:** Add small, pure Python contract modules beside the existing V4 runtime. The provider contract derives `eligibility` from immutable qualification, comparison, utility, security, and checker evidence; it never mutates claims or graph state. The review module has a dedicated synthesis producer and a separate checker that validates hashes and preservation without generating or repairing the synthesis artifact.

**Tech Stack:** Python 3 standard library, `unittest`, JSON fixtures, existing V4 repository conventions.

## Global Constraints

- Preserve `PUBLIC_CORE` as the offline fallback and never execute an unqualified external provider for formal work.
- Keep `qualification_status`, `comparison_decision`, and `eligibility` independent and deterministic.
- Formal eligibility requires behavior evidence, acceptable utility/security status, an exact commit/source hash, and a distinct checker.
- Reviewer synthesis must be generated by a dedicated synthesis provider/process; `review-synthesis-checker` only validates it.
- Do not modify the main installation or vendor external code.
