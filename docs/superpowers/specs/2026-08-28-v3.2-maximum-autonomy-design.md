# V3.2 Maximum Autonomy Design

Date: 2026-08-28  
Baseline: `origin/main` at `6b34dcba551bdf200c2d7dd49bcb6b6057ef67c4`  
Target: `v3.2` branch, V3.2.0 release candidate

## Intent and non-negotiable boundaries

V3.2 adds a maximum-autonomy operating mode for the existing evidence-bound
research OS. It increases execution continuity and recovery while preserving
author control over scientific judgment, ethics, private data, resource
commitments, and irreversible external actions.

The v3.1.1 provenance, evidence, research graph, scientific gates, and
regression contract remain authoritative. New code may add records and
decisions, but it may not upgrade a declared or pilot result, bypass a frozen
protocol, infer claim support, rewrite graph history, or turn a deterministic
harness into a model evaluation. No third-party dependency, skill installation,
network write, publication, submission, or tag rewrite is introduced.

## Layered architecture

### 1. Policy and authorization control plane

`scripts/autonomy.py` is the only public authorization boundary. It reads a
versioned policy object and returns a structured decision for every action:

```text
authorize(policy, action, scope, risk, reversible, actor, now)
  -> {status, action, risk, reason, authorization_id, requires_author}
```

The policy records mode, resource budgets, permissions, fail-closed behavior,
and standing authorizations. `maximum-autonomy` permits bounded, reversible,
local work inside the declared envelope. High-risk actions remain conditional;
external writes, publication, and submission always require explicit author
authority. Expired, revoked, scope-mismatched, or over-budget standing
authorizations never authorize an action.

`auto_hire_gate` is a separate policy decision used by the director before an
employee can be activated. A candidate must have an exact immutable reference,
license and source audit, passed behavior and security evidence, a declared
permission scope, and a risk level within the policy cap. A missing or weak
condition yields `BLOCKED` or `CONDITIONAL`; it is never silently promoted.

### 2. Audit integrity layer

Authorization decisions, standing-authorization changes, director decisions,
recoveries, and completion checks append canonical JSON events to
`.autonomy-audit.jsonl`. Each event contains a sequential ID, UTC timestamp,
actor, operation, inputs, decision, predecessor hash, and event hash. The
`verify_audit` operation recomputes the complete chain and fails on mutation,
reordering, truncation, malformed JSON, or a missing predecessor. The audit log
is additive and separate from the existing graph event log; both must verify.

### 3. Director and session layer

`scripts/director_loop.py` implements a bounded director loop. It persists a
session document containing a stable session ID, policy hash, graph projection
hash, iteration, current node, completed work, checkpoints, recovery count,
last decision, and blocked reason. A new invocation resumes only when the
policy and graph identity still match; otherwise it stops with an explicit
`CONDITIONAL`/`BLOCKED` decision. The loop calls existing graph readiness and
transition APIs, never edits graph events directly, and records every choice in
the audit chain.

Self-healing is narrow and deterministic: a failed or interrupted job is
reopened through the existing graph API, partial outputs remain quarantined by
the job runtime, and the director retries only within the declared retry and
iteration budget. A repeated failure becomes `BLOCKED` with a recovery report;
the loop cannot invent evidence or mark a node `PASS` without the existing
evidence contract.

### 4. Completion contract and dashboard layer

`scripts/completion_contract.py` evaluates an explicit completion contract. It
requires clean policy and audit chains, valid graph projection/rebuild, all
scientific gates required for the requested disposition, provenance/evidence
checks, deterministic full-paper E2E status, and an explicit list of residual
risks and author actions. Critical failures are fail-closed; statuses are
`PASS`, `CONDITIONAL`, or `FAIL` and include evidence references.

`dashboard.py` gains a v3.2 section exposing mode, authorization posture,
session/resume status, audit head, recovery count, completion disposition, and
the same residual risks. It is a projection only and never changes research
state.

### 5. Deterministic full-paper E2E layer

`scripts/full_paper_e2e.py` runs a local, public, synthetic fixture through the
full workflow: brief, literature identity/retrieval, claim relation,
innovation/feasibility, protocol freeze, executable output, observed and
verified evidence anchors, figures/table and manuscript artifacts, validation,
review, package manifest, and completion contract. Every generated file is
written by the command that claims it, content-addressed, and tied to the
current commit. The result is labeled `HARNESS_SELF_TEST`, explicitly not a
scientific result or model behavior evaluation. Running it twice with the same
fixture and commit yields the same semantic result and hashes.

## State and compatibility

Initialization keeps the existing `.research-state` layout and v3.1.1 files.
It adds `autonomy_policy.json`, `completion_contract.json`, and
`director_session.json` with additive schema fields. Legacy state remains
readable; migration never deletes or rewrites the source. Existing v3.1.1
scripts retain their version and contracts where tests depend on them, while
v3.2 entry points identify themselves as `3.2.0`.

## Failure handling

- Malformed policy, audit, graph, session, or completion input returns a
  structured `FAIL`/`BLOCKED` result without partial mutation.
- Any audit-chain mismatch stops the director and completion evaluation.
- Authorization is deny-by-default for unknown actions, missing permissions,
  expired standing grants, private-path violations, resource overrun, and all
  irreversible external effects.
- Self-healing preserves failed artifacts and appends a recovery event; it does
  not delete failures or broaden scope.
- A release candidate is ready only when the complete local CI-equivalent gate,
  the deterministic full-paper E2E, and the completion contract pass. Hosted
  model behavior remains `NOT_RUN` unless an authorized isolated adapter exists.

## Verification strategy

Behavior tests are written before implementation for policy decisions, grant
expiry/revocation, AUTO_HIRE risk, hash-chain tamper detection, resume and
self-healing boundaries, completion fail-closed behavior, dashboard projection,
and deterministic E2E output. The unchanged v3.1.1 suite remains a regression
gate. The final gate runs unit/integration tests, release/schema/registry/
privacy/security checks, both smoke paths, graph rebuild, and the new full-paper
E2E and completion-contract checks.
