# V4 Private Ultra Design

## Objective

Extend the current V4 working state with a quality-first private provider layer while preserving the independently functional public core and all existing scientific, evidence, authorization, publication, and release authorities.

## Architecture

`PUBLIC_CORE` remains the offline, distributable fourteen-role team. `PRIVATE_ULTRA` is an optional local overlay whose providers are selected from pinned candidates by task-specific behavior evidence. The overlay may select one primary provider or a non-redundant complementary ensemble, but every formal producer must be qualified and every critical node must retain a distinct checker.

The public repository contains only independently implemented routing, schemas, benchmark tasks, source metadata, and target role mappings. Local provider contents and private filesystem paths stay outside public commits. License is recorded for provenance and redistribution decisions; it is not a quality score.

## Provider Qualification

A candidate is formal-eligible only when it has an exact 40-character commit, an installed local entrypoint, a passed static audit, a completed hash-bound behavior trial for the requested capability, and a separate checker identity. Static audit, popularity, repository description, and architecture claims cannot qualify behavior.

PRIVATE_ULTRA selection returns one of `SINGLE_PRIMARY`, `ENSEMBLE_COMPLEMENTARY`, `EXTERNAL_BETTER`, `INTERNAL_BETTER`, or `NO_QUALIFIED_PROVIDER`. A complementary provider must add at least one declared capability not supplied by the primary for the concrete task. PUBLIC_CORE is always retained as fallback.

## Team Mapping

The role map keeps the Research Director plus thirteen specialists. Each role declares target primary providers, complementary providers, checker candidates, and optional adversarial providers. V4's control plane remains the primary authority for Research Director and Publication Editor; third-party orchestrators are advisory or execution providers only.

## Behavior Evaluation

The benchmark suite includes the requested skill candidates and system-level comparators. Each comparator receives a public, concrete task and must produce a hash-bound artifact. V4 produces a comparable artifact. Two blind judgments run in counterbalanced order and provide dimension-level evidence. Missing runs, incomplete outputs, stale hashes, or one adverse parity ordering fail closed.

The TTA project remains the field regression. Experiment process completion is distinct from publication sufficiency. Statistics, mechanism analysis, ablations, reviewer completeness, additional experiments, manuscript revision, and submission readiness remain required after the campaign finishes.

## Release Boundary

This work is committed and pushed to the current feature branch for review. It does not merge, tag, release, publish a manuscript, or claim benchmark superiority. Until real comparator runs and TTA publication gates pass, `recommended_merge` remains `NO`.
